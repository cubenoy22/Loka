synchronously on the app's own thread and the app's click handler pumps the modal
common-file-dialog loop itself, so SendMessage(BM_CLICK) does not return until the
dialog is dismissed. My first attempt tried to also drive the dialog's Edit control by
window text/class heuristics after the click returned -- that class detection
(comparing to "#32770") never matched a distinct top-level window for the app's PID
within my 5s poll, so scripted typing into the dialog was not reliable and I could not
drive it that way. Per the coordinator's correction, I stopped trying to type into the
dialog; the user drove the actual file selection by hand for every Open... invocation
