# ScrapbookUI macOS-arm shape review

Ranked candidates considered for the macOS slice:

1. **This example becomes a bundle while older example targets are plain
   executables.** The difference is load-bearing rather than cosmetic:
   `File::Application()` on macOS resolves `NSBundle`'s Resources directory,
   so the package owner needs a real bundle resource boundary. The target owns
   that packaging shape; app-facing code still asks for `ASSETS.LRP`.
2. **The modern package is copied to a second, generically named staging
   file before CMake embeds it.** `MACOSX_PACKAGE_LOCATION` preserves a source
   file's basename, so the explicit staging cell is what keeps
   `ASSETS-modern.LRP` a bake-side name and `ASSETS.LRP` the runtime name. The
   staging directory is target-local build output, not mutable application
   state.
3. **`MacOSMain.mm` repeats the repository's manual autorelease-pool
   bootstrap.** It is a deliberate platform-seam twin of the other macOS
   examples, including the documented Leopard/PPC shutdown behavior. It adds
   no ARC assumption, direct ivar access, or platform state to the common
   Scrapbook node.
4. **Header globbing parallels the other macOS example targets.** Headers are
   listed only for project/bundle visibility and are not runtime inputs. No
   API or field exists solely so a test can observe the macOS arm.
5. **macOS verification is absent from this environment.** The arm reuses
   `LokaMacOSCore`, `NSImage` decoding, and `MacAppLocation`; no fallback
   decoder or guessed non-bundle path was added. The PR must remain Draft until
   the maintainer records macOS build and runtime verification.

Implementation-complete gate:

- New door/call site: `MacOSMain.mm` converges on the same
  `RunApp<ScrapbookAppConfig>` bootstrap as the other platforms.
- New target/resource: `ScrapbookUIMacOS` owns one staged bundle resource and
  parallels existing macOS example link/include/no-ARC settings.
- Teardown/reclamation: no runtime lifecycle path changed; the process pool
  follows the repository's existing macOS bootstrap policy.
- Configuration absence: without `APPLE` the Objective-C++ language, bundle,
  and resource staging do not exist; common and Retro68 builds retain their
  own complete target shapes.
- Test-observability APIs: none added.
