# Show shorthand shape review

## Gate 1: design-complete review

- Repeated shape: the new `State<bool>& << child` door parallels the existing
  `Show(State<bool>&)` factory followed by `ShowDefinition::operator<<`. It
  delegates to those two existing doors; it does not duplicate branch storage,
  child cloning, composition, or runtime behavior.
- Missing wall: without the overload, misuse is an ordinary compile error. The
  overload's left operand is always-on and exactly `State<bool>&`, so another
  `State<T>` cannot select it. An unsupported child still fails at the existing
  `ShowDefinition::operator<<` wall.
- Boxes and lines: the input state enters a stack-local `ShowDefinition`; that
  definition owns its existing true/false `FragmentDefinition` values, and the
  existing member operator clones or adopts children according to its current
  rules. No field, identity token, callback, or lifetime edge was added.
- Repeated manual step: there is none. Future node-definition types use the same
  forwarding template and the existing Show child door.
- Test-shaped API: no production shape was added for observability. The recursive
  comparison helper exists only in `FlowDslTests.cpp` and walks public definition
  and branch interfaces already used by composition.

## Gate 2: implementation-complete review

- Added production surface: one free `operator<<` template in `loka::app`. It
  parallels `Show(...)` plus the existing member `operator<<` and delegates both
  construction and child insertion to them. No fields, virtuals, teardown paths,
  reclamation paths, state writes, or platform calls were added.
- Added test surface: one definition-tree comparison helper and two test blocks.
  One compares shorthand and explicit single-child compositions; the other pins
  multi-child chaining. The neighboring existing `Show(...)` runtime test is
  unchanged.
- Build-dependent walls: none disappear in release or Classic builds. The
  signature remains C++98-compatible, and the Retro68 collision-probe translation
  unit compiled with warnings as errors.
- Intentional asymmetry: `Show(const State<bool>&)` remains supported, while the
  shorthand accepts only non-const `State<bool>&`, exactly as specified. Adding a
  const shorthand overload would silently widen the agreed API.
- Lookup line: the operator lives in `loka::app`, so app code obtains it through
  the same explicit DSL namespace import used for `Button`, `Cell`, and `Show`.
  It does not add a global name that can collide with Universal Interfaces.
- Potential いびつ considered: the right operand is a forwarding template rather
  than a separately repeated overload for each child form. This makes overload
  selection broad after `loka::app` is imported, but the exact `State<bool>&`
  left operand keeps the new syntax isolated and the existing Show member remains
  the compile-time acceptance wall. Repeating four free overloads would create a
  second child-shape family that could drift.
- Complexity gate: one public DSL door is the only risk flag. Ownership,
  lifecycle, dirty routing, boundaries, platform seams, and mutable state are
  unchanged, so the change stays in the normal 0-1 flag tier.
