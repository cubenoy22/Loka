# Immutable control binding shape review

## Gate 1: design-complete review

- Repeated shape: `EditText::text`, `PopupMenu::selectedIndex`, and
  `ScrollBar::value` are the same two-way-binding family. The existing
  `MutableState<T>` type already names write authority, so each door and stored
  pointer now uses that type. Read-only control inputs such as `enabled` remain
  `State<T>*`; no second mutability model was added.
- Missing wall: without this wall, the platform arms accept an immutable state,
  fail their mutable-state probe, and discard user input. That is an app-visible
  correctness failure, so the wall is always-on overload resolution rather than
  an audit gate or debug assertion. It remains present in C++98, Release, and
  Classic builds.
- Boxes and lines: the application or owning Node/Boundary still owns the
  mutable state, control Props borrow it, and platform projection writes through
  the same borrowed edge. The change tightens the edge type; it adds no owner,
  lifetime token, callback, or cleanup path.
- Repeated manual step: lifecycle-owned state needs a `NodeState<T>` adapter at
  every two-way binding door. The overloads follow the existing
  `OpenFileDialog::result` precedent and keep the internal unwrap inside the
  framework. A generic wrapper would not remove the typed control fields or
  overloads and would add a second binding concept, so it was not introduced.
- Test-shaped API: no production surface was added for observability. The C++98
  signature probes live only in `NullPlatformContractTests.cpp` because this
  repository has no negative-compile test rail.

## Gate 2: implementation-complete review

- Doors and fields: `EditTextProps::text_`,
  `PopupMenuProps::selectedIndex_`, and `ScrollBarProps::value_` changed from
  `State<T>*` to `MutableState<T>*`. Their raw-pointer constructors/setters and
  Definition forwarding doors changed in parallel. `IPopupMenuProps`' existing
  getter now returns the same mutable type. No field or virtual was added.
- NodeState doors: Props/Definition overloads accept `NodeState<T>` for the
  lifecycle-owned case. They parallel the existing OpenFileDialog result door.
  HelloWorld now passes its editable `fruitIndex_`, `heightInput_`, and
  `weightInput_` handles directly; display-only states still pass `.state()`.
- Dangerous API review: five new framework-internal calls to
  `dangerouslyMutableState()` are deliberate adapters at the binding doors.
  They do not appear in example/DSL call sites, expose no raw pointer to the
  caller, and immediately store into a `MutableState<T>*` field. This is the
  same reviewed shape as `OpenFileDialog::result`; making HelloWorld unwrap the
  state itself would violate the NodeState internal-surface policy.
- Teardown and reclamation: none changed. All platform binding, unbinding,
  detach, retirement, and deferred-reclaim paths are untouched.
- Build-dependent checks: the production wall is a parameter/field type and
  cannot disappear under `NDEBUG`. The test assigns each mutable overload to an
  exact member-function-pointer type and uses C++98 SFINAE to prove that the old
  immutable overload is absent.
- Evidence versus tree: the diff contains three tightened binding families, one
  surfaced example update, and one registered contract test. No platform
  implementation or State mutability behavior changed.
- Potential distortion considered: platform contexts still store some bindings
  through their read-capable `State<T>*` observation members and retain their
  defensive mutable probe. Those paths are downstream of Props fields that can
  now only contain `MutableState<T>*`; removing the defensive platform code is
  unnecessary churn for this app-facing wall.
- Lifecycle questions: no release moved outside a clock; no owning edge was
  added; the existing logical-to-native doors are unchanged; the mutability
  invariant is pinned by an always-on type wall and a contract test; retire,
  detach, and reclaim vocabulary is unaffected.
- Complexity gate: the only risk flag is the explicitly reviewed internal
  `dangerously*` adaptation. There are no new owners, mutable flags, callback
  lifetimes, cross-boundary sharing paths, fallback behavior, or platform
  workarounds.
